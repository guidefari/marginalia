# Prepare faithful narration without rewriting articles

**Keep Kokoro through OpenRouter and build a small, source-linked preparation layer around the existing structured-generation path.** Reuse extraction, normalization, pronunciation, and accessibility conventions rather than seeking an end-to-end article-rewriting model. The reviewed projects and model documentation do not establish a ready-made adapter that preserves arbitrary articles, tables, code, and figures without omissions or inventions. The research recommends bypassing the LLM for ordinary prose once deterministic normalization is adequate. This release instead honors the requested LLM preparation step for every passage, including prose, using constrained exact-source edits and the reader's Quick model; its additional cost and latency are explicit. Preserve the original article and its paragraph mapping, and make missing visual evidence explicit. Nothing in this research warrants another speech provider, a new service, or fine-tuning.

## Reuse components, but own the fidelity contract

The existing extractor, DOM-to-paragraph mapping, speech provider and player are the starting point, not work to rebuild. Preserve them where adequate. **Mozilla Readability is a reference or extraction fallback, not a narration engine**: it returns structured article HTML and metadata as well as flattened text, and does not sanitize untrusted HTML. Retain structure before requesting any adaptation ([Readability](https://github.com/mozilla/readability#readme)).

For normalization, distinguish written-to-spoken conversion, TN, from speech-to-written conversion, ITN. NVIDIA NeMo Text Processing supplies constrained WFST grammars for supported token classes; its context-aware approach can rank alternative verbalizations. The documented `neural_text_normalization_t5` model tags spans before verbalizing them, but its archived documentation also describes semantic errors on long numbers. **Benchmark NeMo only if observed normalization failures justify its Python/Pynini integration burden**; it does not solve table or chart adaptation ([NeMo package](https://github.com/NVIDIA/NeMo-text-processing), [WFST/context-aware TN](https://docs.nvidia.com/nemo-framework/user-guide/24.12/nemotoolkit/nlp/text_normalization/wfst/wfst_text_normalization.html), [neural TN](https://docs.nvidia.com/nemo-framework/user-guide/24.07/nemotoolkit/nlp/text_normalization/nn_text_normalization.html)).

Misaki, Kokoro's pronunciation frontend, is worth studying for pronunciation overrides and grapheme-to-phoneme handling. Its existence does **not** establish that Marginalia's hosted Kokoro endpoint exposes those controls. Start with scoped pronunciation preferences and test what that endpoint actually accepts ([Misaki](https://github.com/hexgrad/misaki)). Audiblez provides Kokoro segmentation and resumability examples, but its fixed-tag extraction and automatic period insertion are insufficient for general article fidelity. READ2ME separates full-text narration from generated podcasts, but its inspected full-text route largely passes extracted text to TTS; neither project supplies the missing semantic adapter ([Audiblez implementation](https://github.com/santinic/audiblez/blob/main/audiblez/core.py), [READ2ME worker](https://github.com/WismutHansen/READ2ME/blob/main/utils/task_processor.py)). Study these patterns rather than adopting either application wholesale; pin commits before copying code.

## Preserve relationships instead of making prose conversational

WAI guidance supports meaningful reading order, heading hierarchy, table-header relationships, and equivalent-purpose image alternatives. DAISY adds useful conventions for navigating and escaping secondary structures. **Reuse these semantics, not an EPUB implementation or a claim of automatic WCAG compliance** ([WAI sequence](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html), [DAISY reading order](https://kb.daisy.org/publishing/docs/html/order.html)). The following are proposed Marginalia policies, not prescribed speech timings or universal narration rules.

| Content | Preparation policy |
| --- | --- |
| Headings, lists, quotations, notes | Speak headings once in place; retain rank for navigation and add a section boundary. Preserve numbered order, nested membership, attribution, and entry/return boundaries. Do not promote bold prose into an invented heading. ([WAI headings](https://www.w3.org/WAI/tutorials/page-structure/headings/), [DAISY structure](https://kb.daisy.org/publishing/docs/html/order.html)) |
| Punctuation, numbers, abbreviations | Preserve prose by default. Use punctuation and block boundaries for pacing; do not globally add periods or remove symbols. Normalize typed spans with locale and context, preserving signs, precision, units, and uncertainty. Prefer source-provided expansions; do not guess ambiguous dates or acronyms. Keep pronunciation aliases separate from source spelling. ([DAISY abbreviations](https://kb.daisy.org/publishing/docs/html/abbr.html), [normalization examples](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices#text-normalization)) |
| Tables | Preserve caption, units, header chains, every substantive cell, and footnotes. Prefer deterministic traversal of extracted relationships, such as row label followed by column label and value. Blank is not zero; forecast is not actual. Keep long detail navigable and explicitly skippable, never silently replaced by a trend summary. Unrecoverable header relationships produce an unresolved block. ([WAI tables](https://www.w3.org/WAI/tutorials/tables/), [DAISY synchronized tables](https://kb.daisy.org/publishing/docs/sync-media/tables.html)) |
| Code and math | Retain exact source and position. Announce code boundaries and provide a technical reading that distinguishes identifiers, literals, operators, and significant indentation. Long code needs a full-detail segment, not an automatic explanation substituted for it. Preserve structured math and test grouping-sensitive speech. No universal code-to-speech grammar was established here. ([DAISY code structure](https://kb.daisy.org/publishing/docs/html/order.html), [MathML caveats](https://kb.daisy.org/publishing/docs/html/mathml.html)) |
| Charts and images | Ignore confirmed decoration. Prefer author alt text, captions, long descriptions, and underlying data, retaining distinct information without exact duplication. A chart alternative must preserve relevant axes, units, scales, series, and uncertainty. If evidence is missing, identify the figure, read available caption text, and disclose the gap. Never invent values, identities, trends, or causation. A caption alone does not establish complete coverage. ([WAI alternatives](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html), [complex images](https://www.w3.org/WAI/tutorials/images/complex/)) |

Unreviewed image interpretation should not enter the first increment. Even a vision-capable quick model does not establish factual reliability. Missing-image notices permit an honestly labeled partial rendition; they do not make it equivalent to the complete article.

## Prepare validated blocks ahead of playback

Extend the existing block mapping with stable source IDs, source hash, kind, order, paragraph indices, and relevant structure. Retain table-cell relationships, code text, figure evidence, language, and source spans. Map each resulting speech segment back to its source block and existing paragraph indices so paragraph following survives normalization and one-to-many segmentation. Give non-paragraph objects their own anchors rather than pretending they are ordinary paragraphs.

The proposed structured-output contract is one disposition per requested block: `unchanged`, `adapted`, or `unsupported`, plus span edits containing `exactOriginal`, `replacement`, and an allowlisted reason, along with warnings and separate delivery hints. Allow only pronunciation, token normalization, and source-grounded structure verbalization. Code must verify source matches, valid non-overlapping spans, unique IDs, and complete block accounting before applying edits. Prefer deterministic table verbalization from cells over generated replacement paragraphs. **Schema-valid edits are not proof of semantic fidelity**; names, numbers, negation, qualifications, and attribution still need checks.

Treat article text as untrusted data, including passages resembling model instructions. Do not permit summaries, added examples, invented speakers, or free-form whole-article regeneration. On invalid edits, retain safe original prose; on structures that cannot be faithfully spoken, disclose an unresolved block instead of falling back to flattened text or a summary.

Prepare a coherent initial group of blocks, validate it, and begin synthesis while bounded background work prepares the next groups. Supply neighboring context and source-grounded definitions without asking the model to regenerate that context. Queue only validated output and keep segment order stable through retries, cancellation, and resume. Cache preparation by source hash and policy/prompt/model/normalizer versions; cache audio separately by prepared content, pronunciation rules, voice, and TTS configuration. Dictionary-driven segment invalidation has an existing implementation precedent ([ElevenLabs pronunciation dictionaries](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices#pronunciation-dictionaries)).

Keep canonical speech text free of control markup. Store semantic boundaries separately and translate them only into tested endpoint controls or application-managed gaps. Do not assume Kokoro accepts SSML or that device voices honor it consistently; browser boundary and mark events depend on engine support. Preserve explicit segment completion/error tracking rather than relying on optional events ([Web Speech specification](https://webaudio.github.io/web-speech-api/#utterance-attributes), [utterance events](https://webaudio.github.io/web-speech-api/#utterance-events)).

## Evaluate fidelity before choosing a different model

Compare unchanged-text, normalization-only, and constrained-adaptation variants using the same Kokoro voice, then test the supported device-speech path separately. Reuse the reader-owned quick model first. Escalate difficult blocks only if measured results justify it; no model benchmark in these notes supports a replacement model recommendation.

Build a hand-reviewed fixture set covering long articles with late exceptions and distinctive endings, nested headings/lists, quotations and footnotes, merged-header tables with blanks and negative forecasts, ambiguous dates and acronyms, code operators/indentation, grouped equations, informative and decorative images, incomplete charts, and instruction-like article text. Test extraction, prepared text, and audio separately. **Require 100% substantive-block accounting and zero observed critical fidelity errors on the release fixtures**: no silent omission, invented claim, changed value/unit/sign, lost qualification, duplicate segment, or reordered content. These are proposed product gates, not WCAG thresholds or guarantees about unseen articles.

Every block must resolve to narration, an adequate alternative, a disclosed gap, or an explicit user-selected skip. Track unresolved gaps separately from complete coverage. Listen to joins and the final paragraph; HTTP success and a correct script do not prove complete audio. Audiblez's extra sentence splitting explicitly addresses Kokoro truncation risk, making endpoint-specific length tests necessary ([Audiblez generation](https://github.com/santinic/audiblez/blob/main/audiblez/core.py)). Back-transcription can flag issues but must not judge technical speech alone. Ask listeners which section they heard, which header/unit belongs to a value, and whether chart evidence was available. Record first-playable latency, completion time, changed-block rate, fallback rate, and critical errors alongside provider/model/voice/policy versions.

## Ship the safe subset while measuring unknowns

Start with source-linked blocks, unchanged prose, heading boundaries, a coverage manifest, and explicit unsupported-structure notices. Then add tested token normalization, simple header-preserving tables, and author-provided figure alternatives through the existing quick-model path where necessary. Complex tables, technical code/math readings, and reviewed visual interpretation should advance independently as their fixtures pass. Until then, label affected renditions partial rather than claiming full article coverage.

The notes contain source and documentation inspection, **not model trials, listening experiments, or an audit of Marginalia's implementation**. Open questions are extraction completeness, hosted Kokoro normalization and pronunciation controls, safe chunk lengths, pause behavior, device-voice consistency, and quick-model semantic error rates. Listener preferences for long tables and code also remain unmeasured. There is no established off-the-shelf coverage-preserving adapter in the reviewed evidence, but that bounded search does not prove none exists.

## Conclusion

The useful implementation boundary is a versioned prepared rendition that can explain every change and trace every spoken segment to the article. This lets Marginalia improve a pronunciation or table reading without modifying the source, invalidating unrelated audio, or hiding an omission. Another model, normalizer, or speech service should be considered only when a logged failure demonstrates a capability the existing path cannot provide.
